
# Проектная документация: Inspector App

## 1. Обзор проекта

**Назначение:** Мобильное Android-приложение для проведения инспекций товаров на складах сети "Магнит".

**Основная концепция:** Приложение функционирует как файловый менеджер для фотографий, сделанных в ходе инспекций. Оно позволяет пользователям создавать инспекции, прикреплять к ним фотографии, сделанные с помощью камеры устройства, управлять этими файлами и выгружать их в облачные хранилища.

## 2. Техническое описание

### 2.1. Стек технологий

*   **Язык программирования:** Kotlin
*   **Архитектура:** MVVM (Model-View-ViewModel)
*   **Сборка:** Gradle с использованием Kotlin DSL
*   **Минимальная версия Android:** API 25 (Android 7.1 Nougat)
*   **Целевая версия Android:** API 34 (Android 14)

### 2.2. Ключевые библиотеки и фреймворки

*   **UI:**
    *   AndroidX AppCompat, Material Components, ConstraintLayout
    *   ViewBinding для привязки представлений
*   **Работа с камерой:**
    *   **CameraX (`androidx.camera`):** Основная библиотека для работы с камерой.
    *   **CameraView (`com.otaliastudios:cameraview`):** Дополнительная библиотека, возможно, для специфических экранов или функций.
*   **Работа с изображениями:**
    *   **Glide:** Для эффективной загрузки и кэширования изображений.
    *   **Picasso:** Альтернативная библиотека для загрузки изображений.
*   **Асинхронные операции:**
    *   **Kotlin Coroutines:** Для управления фоновыми потоками и асинхронными задачами.
    *   **WorkManager:** Для выполнения отложенных фоновых задач.
*   **Хранение данных и бэкенд:**
    *   **Firebase:**
        *   **Authentication:** Для аутентификации пользователей.
        *   **Realtime Database:** Для хранения структурированных данных инспекций.
        *   **Cloud Storage:** Для хранения сделанных фотографий.
    *   **Dropbox SDK:** Для интеграции и выгрузки файлов в Dropbox.
*   **Локальное хранение:**
    *   **DataStore Preferences:** Для хранения простых данных (настройки, токены).
*   **Прочее:**
    *   **MultiDex:** Для поддержки устройств с версией Android до API 21.

## 3. Архитектура приложения

Проект имеет многомодульную структуру, разделенную по функциональному назначению:

*   `com.example.b1void`
    *   `activities`: **(View)** Экраны приложения (Activity/Fragment).
    *   `adapters`: Адаптеры для `RecyclerView` для отображения списков (например, галереи фото).
    *   `viewmodels`: **(ViewModel)** Классы, содержащие UI-логику и состояние экранов.
    *   `usecase`: **(Model/Logic)** Классы, инкапсулирующие бизнес-логику (например, "Создать инспекцию", "Загрузить фото").
    *   `data`: Репозитории и источники данных (Data Sources) для работы с сетью и локальной базой данных.
    *   `models`: Классы данных (data classes), описывающие сущности (например, `Inspection`, `Photo`, `User`).
    *   `cameraFun`: Вспомогательные классы и утилиты для работы с камерой.
    *   `utils`: Общие вспомогательные утилиты.
    *   `workers`: Реализации `Worker` для WorkManager.
    *   `B1VoidApplication.kt`: Кастомный класс Application для инициализации библиотек и зависимостей.

## 4. Основные компоненты и экраны (Activities)

*   `SplashActivity`: Стартовый экран, точка входа в приложение. Вероятно, выполняет проверку авторизации.
*   `MainActivity`: Главный экран после входа.
*   `CameraActivity` / `CameraV2Activity`: Экраны для фотосъемки.
*   `FileManagerActivity`: Экран для просмотра и управления файлами (фотографиями).
*   `InspectionAddActivity`: Экран создания новой инспекции.
*   `ShowInspectionActivity`: Экран просмотра деталей существующей инспекции.
*   `ImagePreviewActivity`: Экран предпросмотра сделанной фотографии.
*   `EditImageActivity`: Экран для редактирования изображения (возможно, добавление пометок).
*   `WorkerActivity`, `AdmActivity`, `AdmLogActivity`: Экраны для административных функций или для отображения статуса фоновых задач.

## 5. Разрешения (Permissions)

Приложение запрашивает следующие разрешения:

*   `CAMERA`: Для фотосъемки.
*   `RECORD_AUDIO`: Для записи видео (хотя фокус на фото, возможность может быть заложена).
*   `READ_EXTERNAL_STORAGE` / `WRITE_EXTERNAL_STORAGE`: Для сохранения и чтения фотографий из галереи/памяти устройства.
*   `INTERNET` / `ACCESS_NETWORK_STATE`: Для взаимодействия с облачными сервисами (Firebase, Dropbox).

## 6. Сборка и запуск

### Сборка APK
Для сборки отладочной версии приложения (debug APK) выполнить команду в корне проекта:
```bash
./gradlew assembleDebug
```

### Запуск на устройстве/эмуляторе
Открыть проект в Android Studio и запустить на выбранном устройстве.
