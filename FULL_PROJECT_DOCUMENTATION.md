# Полная документация проекта и обзор архитектуры

## 1. Обзор проекта

Этот документ содержит всеобъемлющий обзор архитектуры, стека технологий и процесса рефакторинга Android-приложения `b1Void`.

Проект представляет собой приложение для управления и инспекции документов. Основные функции включают в себя:
- **Захват изображений с камеры:** Продвинутая функция камеры для фотосъемки, адаптированная для инспекций и сканирования.
- **Просмотр изображений:** Галерея для просмотра и анализа снятых изображений с поддержкой масштабирования.
- **Облачная синхронизация:** Поддержка хранения данных в нескольких облачных сервисах, включая Firebase и Dropbox.
- **Аутентификация пользователей:** Интеграция с Firebase Authentication для управления доступом.

Приложение построено как многомодульный проект Android, что обеспечивает четкое разделение ответственности и высокую масштабируемость.

## 2. Архитектура

### 2.1. Структура модулей

Проект разделен на следующие модули, организованные по принципу `feature` (функциональность) и `core` (ядро):

#### Функциональные модули (`feature`)
- **`:app`:** Основной модуль приложения. Является точкой входа, объединяет все функциональные модули, управляет навигацией и содержит глобальные конфигурации, такие как `B1VoidApplication`.
- **`:feature:camera`:** Полноценный модуль, отвечающий за функциональность камеры. Включает в себя `CameraScreen` (UI), `CameraViewModel` (управление состоянием) и соответствующую навигацию.
- **`:feature:gallery`:** Модуль для отображения галереи изображений. Содержит `GalleryScreen` и `GalleryViewModel` для просмотра, масштабирования и управления изображениями.

#### Модули ядра (`core`)
- **`:core:model`:** Содержит классы данных (`data class`), которые представляют основные бизнес-сущности приложения, такие как `Inspector`, `FolderNode`, `MediaItem`. Эти классы используются во всех слоях приложения.
- **`:core:domain`:** Чистый Kotlin-модуль, содержащий бизнес-логику. Определяет интерфейсы репозиториев (`PhotoRepository`, `FolderRepository`) и варианты использования (`UseCase`), которые оркеструют поток данных между UI и слоем данных.
- **`:core:data`:** Реализует интерфейсы, определенные в `:core:domain`. Содержит реализации репозиториев (`PhotoRepositoryImpl`), которые инкапсулируют логику работы с источниками данных. Также здесь находится база данных Room (`AppDatabase`), объекты доступа к данным (DAO) и `WorkManager` для фоновой синхронизации.
- **`:core:ui`:** Содержит общие элементы Jetpack Compose. Включает систему дизайна (`Theme.kt`, `Color.kt`, `Type.kt`) и переиспользуемые UI-компоненты (например, кастомные кнопки, индикаторы загрузки), которые используются в разных `feature`-модулях.
- **`:core:common`:** Включает общие утилиты, которые могут использоваться во всем приложении. В основном содержит Hilt-модули для предоставления диспетчеров корутин (`@IoDispatcher`, `@MainDispatcher`) и `ApplicationScope` для фоновых задач.
- **`:core:camera`:** Низкоуровневый модуль для работы с аппаратным обеспечением камеры. Содержит реализацию `CameraXController` на базе CameraX и `DeviceQuirksManager` для изоляции кода, специфичного для определенных устройств (например, обходные пути для Xiaomi). Предоставляет вышестоящим слоям простой интерфейс для управления камерой.
- **`:core:network`:** Отвечает за все сетевые взаимодействия. Содержит интерфейс `CloudStorage` и его реализации (`FirebaseStorageSource`, `DropboxStorageSource`), а также Hilt-модули для их внедрения.

### 2.2. Архитектурный паттерн

Кодовая база следует принципам **Чистой архитектуры**, разделяя приложение на три основных слоя:

- **Слой UI (`feature:*`, `:core:ui`):** Отвечает за отображение данных и взаимодействие с пользователем. Включает в себя экраны на Jetpack Compose и `ViewModel`'и. Для взаимодействия между `ViewModel` и `View` используется паттерн **Unidirectional Data Flow (UDF)**, где UI-события отправляются от `View` к `ViewModel`, а изменения состояния и разовые события (one-time events) передаются обратно через `StateFlow` и `Channel`.
- **Доменный слой (`core:domain`):** Содержит основную бизнес-логику и правила. Этот слой не зависит от фреймворков и определяет, *что* приложение делает.
- **Слой данных (`core:data`, `:core:camera`, `:core:network`):** Реализует логику доступа к данным. Отвечает за то, *как* и *откуда* получать данные, будь то из сети, локальной базы данных или аппаратного обеспечения камеры.

### 2.3. Внедрение зависимостей

**Hilt** используется для внедрения зависимостей во всех модулях. Это стандартизирует процесс предоставления зависимостей, упрощает тестирование и улучшает модульность. Ключевые аспекты:
- **`@HiltAndroidApp`:** Используется в классе `Application`.
- **`@Module` и `@InstallIn`:** Применяются для создания Hilt-модулей, предоставляющих зависимости, такие как репозитории, диспетчеры и базы данных.
- **`@Binds`:** Интерфейсы (например, `PhotoRepository`) отделены от их реализаций (`PhotoRepositoryImpl`) и связаны с помощью Hilt-модулей с аннотацией `@Binds`, что обеспечивает слабую связанность и упрощает замену реализаций.
- **Пользовательские квалификаторы:** `@IoDispatcher`, `@DefaultDispatcher` и `@MainDispatcher` используются для внедрения различных типов `CoroutineDispatcher`.
- **`HiltWorkerFactory`:** Обеспечивает внедрение зависимостей в `WorkManager`'ы.

## 3. Стек технологий

- **Основной язык:** **Kotlin**.
- **Сборка:** **Gradle** с **Kotlin DSL (`.kts`)**.
- **UI:** **Jetpack Compose** (основной фреймворк), **Coil** (загрузка изображений).
- **Асинхронность:** **Kotlin Coroutines** и `Flow`.
- **DI:** **Hilt**.
- **Бэкенд:** **Firebase** (Auth, Storage), **Dropbox SDK**.
- **Локальное хранилище:** **Room**, **Jetpack DataStore**.
- **Камера:** **Jetpack CameraX**.

## 4. Статус технического долга (устранен)

В ходе рефакторинга были решены все критические проблемы:
1.  **Утечка памяти в ViewModel:** Устранена утечка памяти в `CameraViewModel` путем удаления прямой ссылки на `Context`-зависимый контроллер и внедрения паттерна UDF для безопасного взаимодействия с UI.
2.  **Ошибки внедрения зависимостей Hilt:** Устранен ряд критических ошибок Hilt, включая:
    - **Нарушение области видимости (Scope Mismatch):** Исправлена архитектурная ошибка, при которой Singleton-компонент (`PhotoRepository`) зависел от Activity-scoped компонента (`CameraController`).
    - **Отсутствующие и дублирующиеся привязки (Missing/Duplicate Bindings):** Восстановлена корректная работа графа зависимостей путем создания и исправления Hilt-модулей (`@Binds`), а также удаления дубликатов.
    - **Конфликт версий Hilt:** Устранена проблема генерации кода, вызванная несоответствием версий Hilt между различными модулями проекта.
3.  **Конфликтующие зависимости:** Удалена сторонняя библиотека `CameraView`, проект полностью переведен на **Jetpack CameraX**.
4.  **"Мертвый" код:** Удалены устаревшие и неиспользуемые блоки кода, связанные с обходными решениями для конкретных устройств.
5.  **Нарушения потоков:** Исправлено некорректное использование `Dispatchers.Main` для операций ввода-вывода.
6.  **Хрупкие хаки:** Логика для конкретных устройств инкапсулирована в `DeviceQuirksManager`.
7.  **Устаревшие асинхронные паттерны:** `postDelayed` заменен на идиоматические корутины (`withTimeoutOrNull`).
8.  **Уязвимости и анти-паттерны:** Устранены риски безопасности (хранение токенов в коде) и анти-паттерн "Service Locator", код переведен на Hilt.
